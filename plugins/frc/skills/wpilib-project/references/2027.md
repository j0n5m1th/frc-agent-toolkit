# WPILib 2027 (alpha) review notes (Java)

For projects whose `build.gradle` uses GradleRIO `2027.*`. Written against **2027.0.0-alpha-8**; the alphas still change, so say "in alpha-8" when you cite a rule. Labels: **[src]** = read in the alpha-8 source, **[log]** = from the changelog or release notes only.

Sources:
- `CL` = https://docs.wpilib.org/en/latest/docs/yearly-overview/yearly-changelog.html
- `RN` = https://github.com/wpilibsuite/allwpilib/releases (v2027.0.0-alpha-6, -7, -8)
- `DD` = allwpilib `design-docs/` (`opmodes.md`, `commands-v3.md`, `commands-v3-state-machines.md`)

## 1. Project and build

- **Java 25.** Source and target compatibility is 25; Gradle is 9.x; ZGC is the default collector. `invalid source release` means the wrong JDK. [log: CL]
- **Import, do not edit by hand.** A 2026 project, or a 2027 alpha-6 or older one, is imported with the VS Code importer; it fixes `edu.wpi.first` imports, Test to Utility and the `DriverStation` split. An alpha-7 project updates in place. Vendordeps must be 2027 builds (alpha-6 and older do not load). [RN]
- **Systemcore image 14 or later** and Driver Station alpha 7 or later. [RN]
- **`simulateJava` no longer works** (confirmed on a real alpha-8 project: exit 1, "has been removed. Use run instead"; `sim_start` now refuses it on 2027). The task exists only to throw "The simulateJava task has been removed. Use run instead." Simulate with the `run` task (`sim_start` picks it for a 2027 project). `simulateExternalJava` still exists for external tools. [log: GradleRIO source]
- **The main class is a factory again:** `RobotBase.startRobot(Robot::new)` in `Main.java`. No `static` fields or setup in `Main`. [src: `Main.java`]
- **Removed tools:** Shuffleboard, SmartDashboard, PathWeaver, RobotBuilder. Suggest Glass or Elastic for dashboards and Choreo, PathPlanner or Bline for paths. [log: CL]
- **AprilTag and CameraServer are vendordeps now**, and `AprilTagFields` lives in `Fields`. [log: CL]
- **The compiler plugin** flags integer division in a floating-point context and checks opmode annotations; its errors say how to suppress them. [log: RN alpha-8]

## 2. Renames and removals

Look for these first; the code will not compile on 2027 until they are gone.
- Packages `edu.wpi.first.*` are now `org.wpilib.*` (for example `org.wpilib.framework`, `org.wpilib.opmode`, `org.wpilib.command3`). `Preferences` moved to `org.wpilib.preferences`. [src]
- Constants and enum values are `ALL_CAPS` (`DriveConstants.LEFT_MOTOR1_PORT`). [src]
- `robotInit()` is gone: set up in the `Robot()` constructor. Test mode is Utility mode (`utilityInit`, `utilityPeriodic`). [src, log]
- `MotorController.set(x)` is `setThrottle(x)`; `stopMotor()` is `disable()`; `MotorControllerGroup` is gone (use `addFollower`). [src: hatchbot example; log]
- Removed hardware: Relay, analog output, SPI, analog gyro, DMA, built-in accelerometer, ultrasonic, Servo, Jaguar, and (alpha-8) Talon and VictorSP. CAN device classes take a `CANPort` value, not an `int`. [log: CL]
- `Command.schedule()` is gone in v2 (section 4); `RamseteCommand`, `MecanumControllerCommand` and `SwerveControllerCommand` are removed. [src, log: CL]
- `Rotation2d.getRadians()`, `getDegrees()` and `getRotations()` return **wrapped** angles. Code that counted turns with them now silently wraps; use a `double` or `Angle`. `Translation2d.getAngle()` returns an `Optional`. `Pose2d.exp(twist)` is `pose.plus(twist.exp())`. [log: CL]
- Raw integer timestamps are **nanoseconds** (`RobotController.getTime()`); NetworkTables and data logs still use microseconds. A `/ 1e6` on a raw timestamp is now wrong. [log: CL]
- `Mutable` units are removed; `Measure` is immutable. [log: CL]
- `speeds` became `velocities` in names such as `ChassisSpeeds` APIs. Trajectory classes were rewritten: expect to rewrite trajectory code. [log: RN]

## 3. Robot classes and OpModes

- **Pick one base.** `TimedRobot` still works. `OpModeRobot` is new: it finds `OpMode` classes and lists them in the Driver Station. [src: `OpModeRobot.java`]
- **Register opmodes with `@Autonomous`, `@Teleop` or `@Utility`** (optional `name`, `group`, `description`, colors). Classes in the `Robot` class's package or below register on their own. A class must be `public`, not abstract, and a subclass of `OpMode`; a name must be unique inside its mode. The compiler plugin checks this. [src]
- **Constructor.** An opmode needs a public constructor taking nothing, or the `Robot` subclass (the template passes `Robot`). Opmodes are built when selected in the DS, and an exception in the constructor **crashes the robot program**. [src, log]
- **Life cycle of `PeriodicOpMode`:** `disabledPeriodic()` while selected and disabled; `start()` once on enable; `periodic()` each period; `end()` on disable; `close()` when deselected. `start()` must return quickly. `addPeriodic` callbacks also run while disabled, so guard actuator code with `isEnabled()`. [src: template, `OpModeRobot.java`; DD]
- **Robot-wide code** lives in the `Robot` class: constructor, `driverStationConnected()`, `nonePeriodic()` (no opmode selected), `robotPeriodic()`, `simulationPeriodic()`. Share hardware by passing `Robot` into the opmode, not with statics. [src: template; DD]

## 4. Commands v2 and v3

Tell which framework a project uses from its imports (`org.wpilib.command2` or `org.wpilib.command3`) and its vendordeps.

**Commands v3** [src: `commandsv3/`, `hatchbotcmdv3`; DD `commands-v3.md`]
- A subsystem is a **`Mechanism`** (an interface, since alpha-7). Mechanisms are built with `run(coroutine -> ...)`, `runRepeatedly(...)` and a `.named("...")` at the end. Look for a missing name.
- A command body is a **coroutine**: it **must `yield()`** (or `wait`, `waitUntil`, `await`, `fork`) inside every `while` loop, or the whole robot freezes. Never store a `Coroutine` in a field or hand it to another thread. [src: `Coroutine.java`; log]
- **The scheduler runs from `robotPeriodic()`:** `Scheduler.getDefault().run()`. Autos are scheduled with `Scheduler.getDefault().schedule(cmd)`, and `Scheduler.getDefault().cancelAll()` in `utilityInit()`. [src: hatchbot example]
- **Cleanup:** `onCancel()` runs when a command is canceled early; `onExit()` runs on **every** exit (alpha-8). Keep both to one quick action, such as setting a motor to 0. [src: `Command.java`]
- **Triggers:** `onTrue`, `ifTrue` (starts the command while true, never cancels it), `onFalse`, `whileTrue`, `retryWhileTrue`, `toggleOnTrue`, `risingEdge`, `fallingEdge`, `multiPress`, `debounce(Time)`. Gamepad triggers come from `CommandGamepad` (`faceRight()`, `faceLeft()`, `rightBumper()`...). [src: `Trigger.java`]
- **Binding scopes (alpha-8):** a binding made inside a command lasts as long as that command; one made inside an opmode lasts as long as that opmode; one made in `Robot` while a mode runs is tied to that mode (autonomous, teleop or utility); anything else is global. A binding made in a scope that has ended stops firing. Look for bindings created in the wrong place. [src: `BindingScope.java`]
- **Disabled safety (alpha-8):** while the robot is disabled, a command that requires a mechanism whose `controllableDuringDisabled()` is false is refused, and a running one is canceled. Override it on a mechanism only when it must move while disabled (rare); it is the v3 form of `ignoringDisable`. [src: `Scheduler.java`]
- **SysId:** v3 has its own `sysid` routine (alpha-8); do not mix it with the v2 `SysIdRoutine`. [log: RN]
- **State machines:** a declarative API on top of v3 (see `DD commands-v3-state-machines.md`). After a no-argument `switchFromAny()`, new states cannot be added. [log: RN]


**Commands v2** (`org.wpilib.command2`) is still the supported base for most teams; the 2027 template is `commandv2` with `RobotContainer`. [src: `commandsv2/`, `templates/commandv2`]
- **The scheduler rules in `checklist.md` still hold:** `CommandScheduler.getInstance().run()` in `robotPeriodic()`, requirements, new command objects.
- **Schedule through the scheduler.** `Command.schedule()` is gone from `Command` in alpha-8 (the changelog says "deprecated"): use `CommandScheduler.getInstance().schedule(cmd)`, and `cmd.cancel()` still works. Look for `cmd.schedule()` left over from 2026. [src: `Command.java`, `CommandScheduler.java`]
- **Autonomous commands stop with the mode.** The template cancels the auto command in `autonomousExit()` and calls `CommandScheduler.getInstance().cancelAll()` in `utilityInit()`. Missing both lets an auto keep driving into teleop or a utility test. [src: template]
- **Controllers:** `CommandGamepad` (`faceRight()`, `faceLeft()`, `rightBumper()`...) replaces `CommandXboxController` and `CommandPS4Controller`; `CommandJoystick` and `CommandGenericHID` remain. `RobotModeTriggers.autonomous()`, `teleop()`, `disabled()` and `utility()` give a `Trigger` for a mode. [src: `button/`]
- **New helpers:** `Subsystem.idle()` (a command that requires the subsystem and does nothing; use it as a default command or to hold a subsystem), `Commands.idle(...)`, `Trigger.ifTrue`. [src]
- **Removed:** `RamseteCommand`, `MecanumControllerCommand`, `SwerveControllerCommand` and the control subsystems. Replace them with your own command that calls the kinematics and controllers. [log: CL]
- **Choosers:** `SendableChooser` and `SmartDashboard.putData` are replaced by `Selectable` and `Tunables.publish` (section 5); the v2 template's `Autos` and `getAutonomousCommand()` pattern is unchanged.
- **v2 or v3?** Both work on 2027, and they do not mix: a v2 `Subsystem` is not a v3 `Mechanism`. Do not rewrite a working v2 robot into v3 as part of a review; say which the team uses and review it as that.

## 5. Telemetry, tunables, logging

- `SmartDashboard`, `SendableChooser` and `Sendable` are replaced. Choosers are **`Selectable<T>`** (`add`, `addDefault`, `getSelected`), published with `Tunables.publish("Autonomous", chooser)`. Values go out with `Telemetry.log("Name", loggable)`, and a class that reports itself implements `TelemetryLoggable`. Migration guides: `telemetry/doc/telemetry.md` and `tunables/doc/tunables.md` in allwpilib. [src: hatchbot example; log: CL]
- A shim lets `Selectable` talk to 2026 dashboards in alpha-8, and it is planned to go away before kickoff. Elastic alpha 9 or newer is needed. [log: RN]
- `DataLogManager.start()` and `DriverStation.startDataLog(DataLogManager.getLog(), true)` stay the way to log. New in alpha-8: match logs are never auto-deleted, low space is reported as an alert, and a log is copied to a USB drive that is plugged in late. [src: hatchbot example; log: RN]
- Epilogue has one entry point and finds generated loggers by service loading. [log: RN]
- `Alert` is `org.wpilib.util.Alert` (in wpiutil), and joystick warnings are alerts. [src, log: CL]

## 6. Driver Station, gamepads, simulation

- **Gamepad:** use `CommandGamepad` (v3) or `Gamepad`. Face buttons are `faceUp/Down/Left/Right`, and axes have a **default deadband**: code that adds its own deadband may now apply it twice. Trigger axes were removed from the gamepad triggers. `DSGamepadChooser` picks the controller. [log: RN alpha-7]
- **`DriverStation` was split** (mainly `MatchState` and `RobotState`); the NetworkTables table `FMSInfo` is now `DriverStation`. [log: CL]
- **`DriverStationDisplay`:** a text display in the DS that accepts ANSI escape codes. [log: RN alpha-7]
- **Simulation:** run it with the Gradle `run` task (sections 1 and 7). The sim GUI is rendered with SDL, lists devices as a slash-separated tree and shows DS alerts. The HALSim DS extension does nothing, so drive the sim from the GUI. Startup still ends with `********** Robot program startup complete **********`. [src, log]

## 7. VS Code and the plugin's tools

The 2027 WPILib extension (a rewrite; commands are `WPILib: ...` in the command palette) maps onto the plugin like this. [src: vscode-wpilib `package.json`, checked 2026-11; plugin tool names are real]

| VS Code command | Plugin tool |
|---|---|
| Build Robot Code / Test Robot Code / run Gradle Clean / Run a command in Gradle | `wpilib_run` (build, test, clean, list tasks) |
| Deploy Robot Code | `wpilib_deploy` (switch required; never on your own) |
| Set Team Number | `wpilib_set_team` |
| Manage Vendor Libraries | `wpilib_vendordep` |
| Open Project Information | `wpilib_info` |
| Start Tool | `wpilib_tool`: Glass, SysId, OutlineViewer, DataLogTool, wpical |
| Simulate Robot Code | `sim_start` (see below) |

No tool exists for: Create a new project, Import a WPILib 2025-2026 Gradle project, Debug Robot Code, Start RioLog, Hardware Sim, Set VS Code Java Home, Check for WPILib Updates. Tell the user to use that command in VS Code.

- **Import before anything else.** A project that came from 2026 or an early alpha shows a build that fails on imports; the fix is the extension's import command, not hand edits. [RN]
- **Java.** `wpilib_info` reports the JDK: it should be 25, from `<WPILIB_HOME>/<year>/jdk`. The alpha-8 installer reuses the `2027_alpha7` folder, and projects keep `projectYear` `2027_alpha7`; a `2027_alpha7` year next to GradleRIO alpha-8 is normal, so do not report it as a mismatch. [checked on a real alpha-8 install] On Linux the 2027 install folder is under `XDG_DATA_HOME/wpilib`, so set `WPILIB_HOME` if the JDK is not found. [log: CL]
- **Simulation has two paths.** The extension's "Simulate Robot Code" runs Gradle `simulateExternalJava`, writes `build/sim/java.json`, then starts the program itself (and asks which simulation extensions to load). The plugin's `sim_start` runs the plain Gradle `run` task instead. Both end at "Robot program startup complete". `simulateJava` throws on purpose. [src: extension and GradleRIO]
- **Tools that no longer exist:** Shuffleboard, SmartDashboard, PathWeaver, RobotBuilder. `wpilib_tool` offers the five that remain.
- **Settings the extension has** (`wpilib.offline`, `wpilib.skipTests`, `wpilib.additionalGradleArguments`, `wpilib.stopSimulationOnEntry`) change what its commands do but do not change the plugin's tools; say so if the results differ between the two.

## Keeping this file current

Written against alpha-8 (checked 2026-11). Before trusting it for a newer build, re-check what changed:
1. Read the release notes for each newer `v2027.0.0-*` tag and the yearly changelog (`CL`). Beta 1 is expected to break vendordeps.
2. Check the claims marked [src] against the new source: `OpModeRobot.java`, `org/wpilib/opmode/`, `commandsv3/.../Trigger.java`, `BindingScope.java`, `Scheduler.java`, `commandsv2/.../Command.java`, and the `templates/` and `examples/` folders.
3. Check GradleRIO's `WPIJavaExtension.java` for the sim tasks (`run`, `simulateExternalJava`, the `simulateJava` poison pill) and vscode-wpilib's `package.json` for command names.
4. Change this file, then run the plugin tests; they check that tool names and file paths in skills are real.
